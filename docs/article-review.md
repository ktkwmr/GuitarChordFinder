# 記事の内容確認（人間がやる）

記事は Claude が書き、**公開（main へのマージ）の前に人間が内容を確認**します（ベースライン §10-7）。
PR を出すと Cloudflare のプレビュー URL ができるので、そこで実際のページを見て確認します。直したい点は PR のコメントか Claude への指示で伝えてください。

## 毎回見ること

| # | 観点 | 見るところ |
|---|---|---|
| 1 | 事実の正しさ | 音楽の説明（チューニングの特徴、よく使われるジャンル、合わせ方、弦への負担など）に間違いや言い過ぎがないか |
| 2 | アプリとの一致 | 記事の説明（ボタン名・手順・条件）がいまのアプリの動きと合っているか。画面写真が古くないか |
| 3 | コード表 | 押さえ方は `chords.js` で計算しているので書き間違いはないが、**選んだコードと押さえ方が実際に弾いて自然か**（アプリの探索結果そのものの良し悪し） |
| 4 | 日本語・英語の自然さ | 直訳っぽい言い回し、用語の不統一（例: オープン G / Open G） |
| 5 | 検索用の文言 | 各記事の `title` と `description`（`scripts/pages/<slug>.mjs` の先頭）が、狙う検索語を含み、内容と合っているか |
| 6 | 権利 | 曲名・歌詞・他人の画像を使っていないか |
| 7 | スマホ | 390px 前後の幅で読みやすいか（表は横スクロール） |

## 今回（2026-10-19、記事 6 本の初版）特に見てほしいところ

| # | 記事 | 確認してほしい点 |
|---|---|---|
| A | 変則チューニング入門 | 「開放弦の響き」はアプリが付けたコード名そのまま。Standard の **Em7(11)**、Drop D の **Em7(11)/D**、DADGBD の **Gadd9/D**、CGDGBD の **Gadd11/C** は表記として違和感がないか（変えるならアプリ側のコード名判定から直すことになります） |
| B | 変則チューニング入門 | 各チューニングの「特徴」欄の一言（ジャンルの例など）は Claude の一般的な知識による。言い過ぎや誤りがないか |
| C | 変則チューニング入門 | 「弦を上げるチューニングは負担がかかる、細めの弦かオープン D＋カポで」という助言の妥当性 |
| D | DADGAD | 「キー D でよく使うコード」と「G のメジャーは開放弦ポジションに良い形がない」の説明。グリッドに選んだ 10 コードが入門向けとして適切か |
| E | オープン G | 「G」のロー（`x 0 0 0 0 0`）は 6 弦をミュートした形（最低音をルートにする条件のため）。開放 6 本を鳴らす形（G/D）を載せるべきか |
| F | オープン G | 「指 1 本で 5 フレットが C、7 フレットが D」「カポ 2 で A、3 で B♭」 |
| G | ドロップ D・オープン D | 「6 弦の 7 フレットと 5 弦開放が同じ音」の確かめ方、「ドロップ D はロックでよく使われる」 |
| H | FAQ | 「表示されない理由」の条件説明（実際は 6 弦を押さえて 5 弦をミュートする形だけ例外あり、を省略している） |
| I | 使い方ガイド | 画面写真の番号と説明の対応、Android の「アプリをインストール」の言い方 |

## 確認が終わったら

1. 直す点があれば Claude に伝える（Claude が直して PR を更新 → もう一度確認）。
2. 問題なければ「マージして」と伝える。マージ後、本番に反映されたかを Claude が確かめる。
3. 公開後、Search Console でサイトマップを再送信する（記事が 12 ページ増えるため）。
