# 記事の内容確認（人間がやる）

記事は Claude が書き、**公開（main へのマージ）の前に人間が内容を確認**します（ベースライン §10-7）。
PR を出すと Cloudflare のプレビュー URL ができるので、そこで実際のページを見て確認します。直したい点は PR のコメントか Claude への指示で伝えてください。

## 毎回見ること

| # | 観点 | 見るところ |
|---|---|---|
| 1 | 事実の正しさ | 音楽の説明（チューニングの特徴、よく使われるジャンル、合わせ方、弦への負担など）に間違いや言い過ぎがないか |
| 2 | アプリとの一致 | 記事の説明（ボタン名・手順・条件）がいまのアプリの動きと合っているか。画面写真が古くないか |
| 3 | コード表 | 押さえ方は `chords.js` で計算しているので書き間違いはないが、**選んだコードと押さえ方が実際に弾いて自然か**（アプリの探索結果そのものの良し悪し） |
| 4 | 日本語・英語の自然さ | 直訳っぽい言い回し、用語の不統一（例: オープン G / Open G） |
| 5 | 検索用の文言 | 各記事の `title` と `description`（`scripts/pages/<slug>.mjs` の先頭）が、狙う検索語を含み、内容と合っているか |
| 6 | 権利 | 曲名・歌詞・他人の画像を使っていないか |
| 7 | スマホ | 390px 前後の幅で読みやすいか（表は横スクロール） |

## 確認が終わったら

1. 直す点があれば Claude に伝える（Claude が直して PR を更新 → もう一度確認）。
2. 問題なければ「マージして」と伝える。マージ後、本番に反映されたかを Claude が確かめる。
3. 公開後、Search Console でサイトマップを再送信する（記事が 12 ページ増えるため）。
